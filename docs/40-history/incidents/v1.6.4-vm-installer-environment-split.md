# v1.6.4 VM installer environment split

## Symptoms

- The GUI opened after the ZIP's Mark of the Web was cleared, but
  `C:\CyberButler` was empty.
- Services failed immediately with `0x00000001`.
- `Get-Command python` resolved to
  `C:\Users\PAN\AppData\Local\Programs\Python\Python313\python.exe`;
  the SYSTEM service account cannot read that per-user path.

## Root causes

1. Core deployment accepted a caller-supplied interpreter and fell back to
   `Get-Command python.exe`; it did not require a runtime inside the install root.
2. The deployment path had no hard assertion that `tools\broker.py` and the
   portable interpreter existed before service registration.

## Fix

- Bundle `python-3.13.17-embed-amd64.zip` and `pip.pyz` under
  `installer/python-embed/`.
- Extract them to `<InstallRoot>\python`, enable `Lib\site-packages`, and install
  the wheelhouse into that interpreter only.
- Use `<InstallRoot>\python\python.exe` for broker, WFP guard, Web UI, OTP mailer,
  and TOTP operations. No global Python fallback remains in core deployment.
- Assert `tools\broker.py`, `python\python.exe`, and `python\pip.pyz` before
  service registration.
- CBP custom rule `CBP-CUSTOM-NO-RAW-PYTHON` rejects bare interpreter commands in
  the core deployment scripts; `CBP-CUSTOM-REQUIRE-BROKER-ASSERT` requires the
  broker assertion marker.

## Verification

- `pytest`: 294 passed, 13 skipped.
- Pester: 141 passed, 0 failed.
- CBP: `CBP_RESULT=PASS gates_ran=9`.
- Portable interpreter smoke test: wheelhouse install and
  `import fastapi, pyotp, qrcode` passed.

## Lesson

CI green is not enough. Static checks must enforce deployment invariants:
absolute interpreter paths and explicit existence assertions for the files that
services dereference at startup.
