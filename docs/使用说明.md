## 七、注意事项（务必看）

1. **QQ 必须处于登录状态**。SnowLuma 注入的是已登录的 QQ 进程；如果开机后 QQ 没自动登录，机器人不会上线。建议在 QQ 设置里开启「自动登录」。
2. **QQ 版本升级可能让 hook 失效**。SnowLuma 的 native hook 与 QQ 版本绑定；QQ 自动升级到新版本后若注入失败，等 SnowLuma 发新版，或回退 QQ。
3. **封号风险**。这是第三方协议端，腾讯不保证兼容；小号也可能被风控/封禁。不要群发、不要高频加好友/发消息。
4. **端口占用**：5099（SnowLuma WebUI）、3000/3001（OneBot HTTP/WS）、6185（AstrBot WebUI）、6199（AstrBot 反向 WS）。改端口要两边同步。
5. **不要把这些端口暴露到公网**。当前全部为本机回环。
6. 修改 SnowLuma 的 OneBot 配置后，WebUI 保存即热重载；修改 AstrBot 的 `cmd_config.json` 后需要重启 AstrBot。

## 十一、语音消息 / 本地语音转文字（2026-10-28 15:25 修复）

**问题**：发语音后报 422 `unknown variant input_audio`。原因是 DeepSeek 的 provider 声明了 `audio` 模态，AstrBot 就把语音原样塞进请求；DeepSeek 只接受 `text / image_url / file`。

**修复一：去掉 audio 模态（已实时生效）**

- `provider.modalities` 从 `["text","image","audio","tool_use"]` 改为 `["text","image","tool_use"]`。
- 这样即使 STT 失败，历史里的语音块也会被替换成文本 `[Audio]`，不会再 422。

**修复二：本地语音转文字（Whisper，不花钱）**

| 项 | 值 |
| --- | --- |
| 识别引擎 | `openai-whisper`（torch 2.14.1 CPU） |
| 模型 | `small`（461 MB），缓存在 `YOUR_USER_PATH\.cache\whisper\small.pt` |
| AstrBot 提供商 | `whisper_selfhost`（`openai_whisper_selfhost`，device=cpu） |
| 默认 STT | `provider_stt_settings = {enable: true, provider_id: whisper_selfhost}` |
| 音频解码 | 便携版 ffmpeg 9.0.2：`tools\ffmpeg-9.0.2-essentials_build\bin`，已加进 `start-bot.bat` 的 PATH |
| 实测 | 5 秒参考音识别约 2 秒，输出「今天天气好好哦，本来想出去晒太阳，顺便再买一根草莓冰淇淋」 |

**流程**

QQ 语音 → SnowLuma 下发 Record → AstrBot 用 ffmpeg 转 wav → Whisper 识别成文字 → 作为普通文本消息进 LLM。

**注意**

- 换更大的模型（`medium`）识别更准但 CPU 更慢；改 `provider.model` 即可，首次会重新下载。
- 如果哪天语音不识别：先确认 `ffmpeg -version` 能跑（PATH 里有便携版），再看日志里 `Whisper 模型加载完成` 和 `Speech-to-text result`。
- 语音转文字结果会直接进入对话上下文，敏感语音仍会发给 DeepSeek，注意隐私。

## 紧急安全加固：锁定 SYSTEM Broker 运行时

> **P0：如果低权限账户可以修改 `tools/` 或 `AstrBot/.venv`，攻击者可以替换 Broker 或其依赖，从而继承 SYSTEM 执行权限。**
> 这不是理论风险；请在启用 Broker 前完成以下 ACL 锁定。

以管理员身份打开 PowerShell，在项目根目录执行：

```powershell
$root = 'YOUR_PROJECT_PATH'
$tools = Join-Path $root 'tools'
$venv = Join-Path $root 'AstrBot\.venv'

takeown.exe /f $tools /a /r /d Y
takeown.exe /f $venv /a /r /d Y

icacls.exe $tools /inheritance:r `
  /grant:r "SYSTEM:(OI)(CI)F" `
  /grant:r "*S-1-5-32-544:(OI)(CI)F" `
  /grant:r "YOUR_SERVICE_USER:(OI)(CI)RX" `
  /grant:r "YOUR_USER_NAME:(OI)(CI)RX"

icacls.exe $venv /inheritance:r `
  /grant:r "SYSTEM:(OI)(CI)F" `
  /grant:r "*S-1-5-32-544:(OI)(CI)F" `
  /grant:r "YOUR_SERVICE_USER:(OI)(CI)RX" `
  /grant:r "YOUR_USER_NAME:(OI)(CI)RX"
```

仓库提供：

- `tools/harden_broker_runtime.ps1`
- `tools/verify_broker_acl.ps1`

`broker.py` 启动时会调用检查器；如果 `tools/` 或 `.venv` 仍可被低权限账户写入，Broker 会拒绝启动。
锁定后，更新项目文件需要管理员权限；这是有意的安全代价。

- Security Gate 在 `on_llm_request` 阶段从 QQ 私聊工具集移除 `astrbot_execute_python`、`astrbot_execute_ipython`、`astrbot_execute_shell`、`astrbot_shell_session`。
- `tools/verify_broker_acl.ps1` 现在也检查服务账户写权限；`tools/` 和 `AstrBot/.venv` 必须是 Administrators 所有，服务账户只能读/执行。
- 这是工具层收紧，不是对任意 Python/Shell/纯文本执行的完整沙箱。

### 游戏模式退出兜底

- 监控进程在 `GAME MODE ON` 时写 `Desktop\大肥鱼专用文件夹\game-mode.state.json`，正常退出时写 `active=false`。
- 新增每分钟运行的 `Game Mode Watchdog` 任务：如果监控进程已消失、状态仍为 active，且没有检测到游戏，则自动执行 `game-mode.ps1 -RestoreOnly`，唤醒 Ollama 并切回 `local_qwen36`。
- watchdog 日志：`Desktop\大肥鱼专用文件夹\game-mode-watchdog.log`。
- 游戏模式卸载模型改为纯 HTTP `keep_alive=0`，不再启动同步 `ollama stop` 子进程。
